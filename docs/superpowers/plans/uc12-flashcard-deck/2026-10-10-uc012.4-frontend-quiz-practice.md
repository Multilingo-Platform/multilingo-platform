# UC012.4 — Kế hoạch triển khai Practice Redis + PostgreSQL Receipt

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development hoặc superpowers:executing-plans khi được chọn để thực thi. Các bước dùng checkbox; tuân thủ TDD. Không tự thực thi kế hoạch trong nhiệm vụ sửa tài liệu.

**Goal:** Giữ phản hồi tức thì ở FE; chuyển snapshot Practice sang Redis, tự ghi nhận khi hoàn thành và cập nhật thống kê đúng một lần.
**Architecture:** Redis giữ phiên có hạn tuyệt đối. PostgreSQL READ COMMITTED dùng ON CONFLICT để phân xử receipt, cập nhật stats/log trong cùng transaction. Redis cleanup chỉ chạy sau commit; dashboard đọc aggregate ngày.
**Tech Stack:** Java21/Spring Boot3.3.4/Spring Security/JPA/PostgreSQL/Flyway/Spring Data Redis; React19/TypeScript/Axios/LocalStorage/Web Audio.
**Spec:** [Practice](../../specs/uc12-flashcard-deck/uc12.4-hoc-tu-vung.md).
**Test Design:** [22 test cases](../../specs/uc12-flashcard-deck/test-design-uc12.4-quiz.md).
**Trạng thái:** kế hoạch đề xuất sau review 2026-10-12, chưa thực thi/không phải test PASS. Giữ tên file cũ, không tạo kế hoạch UC012.4 thứ hai.

## Global Constraints

- FE không chờ HTTP khi chọn, không có nút Nộp bài Practice; tự sync khi hết câu.
- Limit 4–20/default 10; ít nhất 4 thẻ hợp lệ và4 nghĩa phân biệt; filter ALL/NEW/LEARNING/MASTERED/DUE.
- JWT principal/owner; không X-User-Id/default1; validate đủ N câu, options và duration 0–86400.
- Chỉ full completion nhận10 XP/streak, không cap ngày; SRS fields không đổi.
- Receipt/sessionId là identity; hash do BE tính; không DTO idempotencyKey/requestHash từ client.
- Config default session-validity 30m/receipt-retention 24h/transaction-timeout 30s/cleanup-margin 1m; không gia hạn phiên.
- Stats ngày theo Asia/Ho_Chi_Minh và Clock; phút floor; không log thẻ Quiz như SRS.
- BaseEntity Integer IDENTITY/audit; ResponseEntity<ApiResponse<T>>; AppException/ErrorCode.
- Migration mới tên VYYYYMMDDHHMMSS; không sửa/xóa migration đã chạy, không drop bảng cũ trong release này.
- Tất cả logic FE trong features/vocab. Chỉ commit khi người dùng duyệt diff theo GEMINI.md.

## Review Focus

1. Reserve receipt rồi stats fail: rollback tất cả, snapshot còn (ROLLBACK_01).
2. Concurrent cùng/khác body: insert một winner, replay 200 hoặc conflict409 (CONCURRENT_01/02).
3. Receipt cleanup sau đổi config hoặc Redis restore: không thưởng lại phiên quá hạn (EXPIRY_01/PRUNE_01).
4. Stats/log chưa tồn tại, Practice/Test/SRS chạy song song: upsert và lock order (STATS_01).
5. Rollout legacy data và lost-response retry: không drop lịch sử/không cộng trùng (MIGRATE_01/REPLAY_01).

## Task4 — CompletionWriter: ON CONFLICT, transaction và afterCommit

Files: PracticeCompletionWriter.java, QuizPracticeServiceImpl, receipt repository; tests modules/vocab/service/PracticeConcurrencyIntegrationTest.java.
Consumes: snapshot đã kiểm tra owner/expiry, validated body và canonical hash. Produces: stored result; một transaction ghi nhận.

- [ ] RED với hai connections/barrier: cùng body→2 response200; khác body→200/409; lỗi sau reserve/trong stats→rollback; lostresponse→replay; Rediscleanupfail→200.
- [ ] Run mvn -Pvocab-integration -Dtest=PracticeConcurrencyIntegrationTest test.
- [ ] Public writer.record @Transactional(isolation=READ_COMMITTED, timeoutString theo properties). Orchestrator tra receipt trước Redis để replay khi key đã mất; lúc không có receipt đọc Redis và pass snapshot vào writer. Redis key thiếu phải re-read receipt/hash trước410 vì winner có thể vừa commit và cleanup giữa lookup đầu và GET Redis. Connection lỗi trả 503.
- [ ] SQL reserve bắt buộc insert ngay, không defer flush:

~~~sql
INSERT INTO practice_completion_receipts
(user_id,session_id,request_hash,result_json,session_expires_at,processed_at,retain_until,created_at,updated_at)
VALUES (:userId,:sessionId,:hash,CAST('{}' AS jsonb),:expiresAt,:now,:retainUntil,:now,:now)
ON CONFLICT (user_id,session_id) DO NOTHING RETURNING id;
~~~

- [ ] Nếu không insert: SELECT receipt ở statement tiếp theo; hash cùng trả result, khác409; không catch unique trong transaction đã abort. Nếu insert: recheck expiresAt sau khi chờ khóa và trước thưởng, gọi common stats, update result_json đầy đủ; rollback nếu expired/lỗi. Placeholder JSON chỉ tồn tại trong transaction chưa commit.
- [ ] Commit mới trả result. Register afterCommit callback dùng snapshot key; callback bắt Redis connection error, log/metric, không throw. Không cleanup trong finally hoặc trước commit. Không đánh dấu receipt confirmed trong Redis làm nguồn đúng/sai.
- [ ] GREEN: kiểm tra result_json không còn{}, one receipt, 10 XP delta, correct log delta. Transient DB/Redis errors trả 503 cho retry; conflict409; không cam kết mọi lỗi hạ tầng trả 200.
